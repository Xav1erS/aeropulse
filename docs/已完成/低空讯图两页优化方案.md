# 低空讯图两页优化方案

## 一、优化目标

当前版本不需要推翻重做。视觉框架已经成立，下一步应从"功能齐全的界面 Demo"收敛为：

> **一套可信、可解释、能完整演示 AI 数据闭环的产品 PoC。**

核心改善三个问题：

1. **地图页不越界**：只展示公开公告，不输出"能不能飞"或综合风险结论。
    
2. **管理页形成闭环**：从数据源、入库、AI 解析、证据核验到发布地图。
    
3. **所有状态真实可解释**：类型、时间状态、审核状态、地图状态严格分开。
    

这也与方案原本定义的"公开低空管控公告地图化情报工具"一致：不做飞行审批、不判断绝对能飞、不做点位风险查询。

---

# 二、优化后的核心演示链路

建议把现场演示固定为一条完整故事线：

```text
进入管理页
  ↓
查看数据源与采集状态
  ↓
手动提交一条公告
  ↓
AI 抽取时间、地点、类型和证据
  ↓
查看地理范围与时间轴预览
  ↓
人工核验并发布
  ↓
切换到地图页
  ↓
搜索该地点
  ↓
拖动时间轴
  ↓
看到公告图层从"未开始"变为"生效中"
  ↓
打开详情并回溯官方原文
```

这条链路能同时展示：

- 产品定位；
    
- AI 结构化能力；
    
- Human-in-the-loop；
    
- 地图时空价值；
    
- 可信度与合规边界。

# 三、地图页优化方案

## 3.1 页面结构

保留现有全屏地图和浮层视觉，但重新整理信息层级。

```text
┌──────────────────────────────────────────────┐
│ 品牌｜地区选择｜地点搜索              页面导航 │
│                                    数据更新时间 │
│                                              │
│ 图层筛选                               地图控件 │
│                                              │
│                  地图                        │
│                                              │
│              公告详情侧栏                    │
│                                              │
│ 时间选择｜快捷时间｜时间轴｜状态统计          │
└──────────────────────────────────────────────┘
```

### 顶部区域

保留：

- 品牌；
    
- 全国／省／市选择；
    
- 地点搜索；
    
- 地图页／管理页导航。
    

删除或替换：

- `OPS 881`
    
- `LIVE`
    
- "数据服务在线"
    

改为：

> 数据更新于 2026-06-09 15:30 · 当前展示 25 条公开公告

原因是当前页面并不具备真正的全国实时监控能力，"LIVE"容易造成过度承诺。

---

## 3.2 删除点位风险查询

当前地图右键菜单包含"查询此处风险"，并展示高、中、低风险结果。

建议彻底删除：

- 风险查询菜单；
    
- 风险结果弹层；
    
- `riskResult` 相关状态；
    
- 高／中／低风险判断逻辑。
    

右键菜单可保留两个安全操作：

```text
查看附近公告
缩放至此
```

"附近公告"只返回一定地图范围内的公开公告列表，不输出综合风险结论。

---

## 3.3 图层筛选重新分类

当前图例把"管控类型"和"数据状态"混在一起。优化后分为两组。

### 管控类型

|类型|样式|
|---|---|
|临时禁飞|红色实线|
|临时管控|橙色实线|
|备案／安全提醒|黄色|
|长期规则|紫色|

### 展示状态

|状态|交互|
|---|---|
|待核验|灰色虚线，可开关|
|历史公告|默认关闭|
|未来公告|默认开启，低透明度|

这样用户可以清楚理解：

- "临时禁飞"描述公告是什么；
    
- "未开始"描述公告当前处于什么时间状态；
    
- "待核验"描述数据质量。
    

---

## 3.4 时间轴重新定义

当前页面把 `active_count` 显示为"禁飞"、`not_started_count` 显示为"管控"，属于数据语义错配。

应改为：

|数据字段|页面文案|
|---|---|
|`active_count`|生效中|
|`not_started_count`|未开始|
|`expired_count`|已过期|
|`unknown_count`|待核验|

### 建议保留的组件

- 当前选中时间；
    
- 回到现在；
    
- 过去 7 天；
    
- 当前；
    
- 未来 24 小时；
    
- 未来 7 天；
    
- 滑块；
    
- 当前时点状态统计。
    

### 建议弱化的组件

- 播放按钮；
    
- 密度条；
    
- 里程碑动画。
    

播放可以保留用于展示，但不要作为核心入口。

### 时间语义提示

当用户不在当前时间时，顶部显示：

> 正在查看：2026-06-12 14:00 的公告状态

不要继续显示"LIVE"。

---

## 3.5 公告详情卡重构

建议详情卡按以下顺序排列：

### ① 当前状态

```text
临时禁飞
在所选时间下：生效中
```

### ② 时间与范围

```text
生效时间：2026-06-07 08:00
结束时间：2026-06-10 18:00
管控区域：杭州奥体中心周边 1000 米
```

### ③ 来源可信度

```text
发布单位：杭州市某区公安分局
来源等级：P0 政府官方来源
发布时间：2026-06-01 10:30
最近核验：2026-06-09 14:20
```

### ④ 原文证据

突出显示真正支撑时间与区域判断的公告原句。

### ⑤ AI 解析状态

只有后端返回真实值时才显示：

```text
字段抽取置信度 91%
地理解析置信度 88%
```

当前代码在置信度为空时自动显示 85% 和 93%，应删除默认值。

正确逻辑：

```js
detailCard.confidence_score == null
  ? '未评估'
  : fmtPct(detailCard.confidence_score)
```

### ⑥ 官方核验

保留原有免责提示，并把"查看官方原文"作为唯一主按钮。

---

## 3.6 时间轴性能优化

当前滑块拖动和播放可能持续请求图层接口，应改为：

```text
用户拖动滑块
  ↓
前端立即更新时间文案
  ↓
停止拖动 200ms
  ↓
取消上一请求
  ↓
请求新时间点图层
  ↓
局部更新地图
```

技术建议：

- `debounce 200ms`；
    
- 使用 `AbortController`；
    
- 首次进入才展示全屏 loading；
    
- 时间切换使用地图局部 loading；
    
- 播放模式优先用已加载数据前端计算；
    
- 缓存最近 5–10 个时间点结果。

# 四、管理页优化方案

## 4.1 顶部指标改为 4×2

当前使用 `auto-fit`，容易出现第一行七张、第二行一张的失衡布局。

改为固定四列：

|数据来源|AI 处理|发布结果|异常质量|
|---|---|---|---|
|启用数据源|解析成功率|已发布图层|无证据图层|
|本轮候选公告|待人工核验|有效公告|越权文案|

桌面端：

```css
#cards {
  grid-template-columns: repeat(4, 1fr);
}
```

移动端再切换为 2 列。

### 指标增加统计口径

不要只显示"解析成功率 87%"，改成：

```text
87%
本轮解析成功率
20 / 23 条
```

异常卡使用红色或黄色左边线：

- 无证据图层；
    
- 越权文案；
    
- 采集失败；
    
- 地理解析失败。
    

---

## 4.2 入库任务表重构

当前表格重点是状态、相关性、总置信度和审核状态，但无法直接判断为什么可以发布。

建议表头：

|任务|AI 解析|时间|地理|证据|审核|地图|操作|
|---|---|---|---|---|---|---|---|
|标题＋来源|已完成|已归一化|POI＋半径|6/6 已绑定|待确认|未发布|查看审核|

状态示例：

```text
时间：已解析 / 缺失 / 冲突
地理：已落图 / 边界模糊 / 解析失败
证据：6/6 / 缺失 2 项
审核：自动通过 / 待确认 / 已驳回
地图：未生成 / 预览中 / 已发布
```

### 删除表格中的直接"发布"

当前任务列表允许直接点击发布。建议改为：

> 查看审核

最终发布只能在详情工作台完成。

---

## 4.3 抽屉升级为审核工作台

当前 520px 抽屉主要是纵向字段列表，无法同时核对原文、证据和地图。

建议宽度调整至：

```css
width: min(960px, 92vw);
```

采用双栏：

```text
┌──────────────────────────────────────────────┐
│ 解析审核：公告标题                            │
├──────────────────────┬───────────────────────┤
│ 原文与证据            │ 结构化结果             │
│                       │                       │
│ 高亮开始时间证据       │ 开始时间  96%          │
│ 高亮结束时间证据       │ 结束时间  94%          │
│ 高亮区域证据           │ 区域      88%          │
│                       │ 管控类型  93%           │
├──────────────────────┼───────────────────────┤
│ 来源与版本信息         │ 地图预览＋时间轴预览    │
├──────────────────────┴───────────────────────┤
│ 驳回｜保存修改｜确认并发布地图                │
└──────────────────────────────────────────────┘
```

### 审核工作台必须回答四个问题

1. AI 抽取了什么？
    
2. 根据哪一句原文抽取？
    
3. 地图最终会画成什么？
    
4. 为什么允许发布或需要人工审核？
    

---

## 4.4 发布门禁

只有满足以下条件才能点击"确认并发布"：

```text
来源可追溯
AND 关键字段均有证据
AND 时间解析成功
AND 地理结果可预览
AND 不存在冲突
AND 审核人确认
```

按钮禁用时显示原因：

> 无法发布：管控区域缺少原文证据。

不要只把发布按钮置灰而不给解释。

---

## 4.5 手动提交公告优化

当前管理页已经有"手动提交公告"入口，但应统一为明确流程：

### 第一步：提交内容

```text
提交方式：链接 / 正文
公告链接
公告正文
来源名称
关联数据源
来源等级提示
备注
```

### 第二步：提交并解析

按钮文案：

> 提交并进入 AI 解析

### 第三步：任务状态

提交成功后：

- 自动切到"入库任务"；
    
- 新任务置顶；
    
- 显示处理步骤：
    

```text
正文获取 → 相关性判断 → 字段抽取 → 地理解析 → 时间归一化
```

当前代码里已经存在手动提交相关结构，但需要确保弹窗确认按钮实际执行手动提交逻辑，而不是只处理新增数据源和驳回操作。

## 4.6 数据源列表优化

建议增加：

|字段|作用|
|---|---|
|待审核数|衡量数据源产出的审核压力|
|异常次数|暴露反爬、超时、正文获取失败|

操作改为：

```text

```

"立即采集"后使用行内状态，不弹原生 `alert()`。

# 六、视觉系统优化

目前公共 CSS 已经定义了完整的字体、色板、间距、圆角和语义 Token，但两个页面又单独定义了大量 `--ui-*` 变量，导致设计系统存在两套来源。

建议只保留一套：

```css
--color-brand
--color-text-primary
--color-text-secondary
--color-surface
--color-border
--color-success
--color-warning
--color-danger
```

重点清理：

- 地图页自引用变量，如 `--radius-sm: var(--radius-sm)`；
    
- admin 中重复的 `</style>`；
    
- 地图页前后重复的组件样式；
    
- 大量直接写死的十六进制色值；
    
- 全局 input 样式影响 radio；
    
- 原生 `alert()`；
    
- 不可键盘操作的点击 `div`。
    

### 字体依赖

当前公共样式仍通过 Google Fonts 加载部分字体，并引用本地 `/fonts/` 文件。

面试演示版建议：

- 中文 UI 统一使用系统字体或本地字体；
    
- 移除非必要 Google Fonts；
    
- Vue、Leaflet 本地化；
    
- 准备离线静态数据。

# 八、最终验收标准

## 地图页

- 用户能在 10 秒内理解页面展示的是公开公告，不是飞行许可；
    
- 图层类型与时间状态没有语义混用；
    
- 任意时间点的统计与地图图层一致；
    
- 缺失置信度时显示"未评估"；
    
- 时间轴连续拖动不会闪屏或产生大量并发请求；
    
- 页面中不出现"低风险 therefore 可以飞"的暗示。
    

## 管理页

- 用户能完整演示一次手动提交；
    
- 每个关键字段都能找到对应原文证据；
    
- 地图发布前可以预览图层；
    
- 发布失败或按钮禁用时有明确原因；
    
- 发布后任务状态和地图状态同步更新；
    
- 面试官能清楚理解 AI、规则和人工审核各自承担什么责任。
    

## 推荐的最终定位

不是继续增加更多功能，而是把产品做成：

> **"公开公告如何被 AI 发现、结构化、核验，并在地图时间轴中可信呈现"的完整演示系统。**

这会比增加 Agent 问答、点位风险判断或更多地图特效，更能体现 AI 产品经理的判断力。
