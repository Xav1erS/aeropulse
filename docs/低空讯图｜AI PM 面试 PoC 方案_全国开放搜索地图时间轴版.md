# 低空讯图｜AI PM 面试 PoC 方案（全国开放搜索｜地图时间轴版）

## 1. PoC 定位

本 PoC 是一个面向 AI 产品经理面试展示的轻量级产品原型，用于验证：

> AI 是否可以围绕低空飞行管控信息，完成公开数据源管理、公告线索入库、非结构化内容解析、地理范围落图、时间状态判断、地图时间轴展示和证据回溯。

本 PoC 不做飞行审批，不判断“绝对能飞”，也不做面向用户的 Agent 问答。产品定位是：

> **公开低空管控公告的地图化情报工具。**

用户侧核心体验不是“问 AI 能不能飞”，而是：

```text
查看地图图层
   ↓
拖动时间轴
   ↓
查看某一时间点 / 时间段内生效、即将生效或已过期的公开管控公告
   ↓
点击图层查看公告来源、时间、区域、证据和官方核验提示
```

范围策略上，本版采用 **全国开放搜索**：

- 数据源覆盖全国、省、市、区县多层级公开来源；
- 地图支持全国范围浏览，并可按省、市、区县筛选；
- PoC 不预设必须覆盖的城市数量、公告数量或数据源数量，能搜索和采集到多少有效公开信息，就进入多少样本；
- 不承诺生产级全国全量实时监控，重点验证全国范围内数据源管理、AI 入库、地图化和时间轴展示链路是否成立。

与之前版本相比，本版做了三点收敛：

1. **取消用户侧 Agent 提问入口**：不再提供“明天下午某地能不能飞？”这种自然语言问答入口。
2. **取消飞行计划检查面板**：不要求用户输入计划地点、高度、机型等参数。
3. **保留地图时间轴**：用户通过时间轴查看不同时间点的生效图层，点击图层查看详情和证据。

数据源与入库管理页继续保留。它不是单独的“公告提交页”，而是用于管理公开信息来源、采集状态、入库任务和手动补充入口。手动提交链接或正文只是其中一种入库方式，提交后仍然进入统一的 AI 解析、证据绑定、地理解析、置信度评估和人工确认流程。

评估能力不再单独做成一页。PoC 阶段只在数据源与入库管理页中融合必要的质量概览和任务级评估，例如解析成功率、待核验任务数、证据绑定状态、地图发布状态、无证据图层数和越权许可文案次数。更完整的 Golden Dataset、模型评测和安全红队测试保留为方案中的 Evaluate 机制，不抢占现场演示主线。

## 2. PoC 要验证的核心问题

| 验证问题 | 说明 |
|---|---|
| 数据源是否可管理 | 能否清楚展示系统从哪些公开来源获取低空管控信息 |
| 公告入库是否可控 | 自动采集和手动提交能否进入同一条解析管线 |
| AI 是否能稳定结构化 | 能否抽取标题、来源、时间、区域、管控类型和证据 |
| 地理解析是否可用于地图 | 能否把 POI + 半径、行政区、多点列表转成地图图层 |
| 时间状态是否可视化 | 能否通过时间轴展示公告在不同时间点的生效、未开始、已过期和未知状态 |
| 地图图层是否可解释 | 用户点击图层后，能否看到公告来源、时间范围、区域描述和原文证据 |
| 产品边界是否清晰 | 系统是否避免直接承诺“可以飞”，并始终提示官方核验 |
| 质量状态是否可见 | 能否在入库任务层面展示解析状态、置信度、证据绑定和待审核原因 |

## 3. 核心用户场景

### 3.1 场景一：地图浏览与时间轴查看

用户打开系统后，默认进入全国地图。页面展示已解析的公开低空管控图层，并提供时间轴。

用户可以：

- 按全国 / 省 / 市 / 区县查看公开低空管控图层；
- 拖动时间轴，查看某一时间点生效、即将生效、已过期或时间未知的公告；
- 开关图层类型，例如临时禁飞、临时管控、备案提醒、待核验区域；
- 点击地图图层查看公告详情；
- 查看公告来源、发布时间、生效时间、管控区域、AI 抽取置信度；
- 查看原文证据和公告链接；
- 对低置信度或边界模糊的区域展示“需核验”标识。

用户不需要输入自然语言问题，也不需要填写完整飞行计划。地图和时间轴就是主入口。

---

### 3.2 场景二：公告详情与证据回溯

用户点击一个地图图层后，系统展示公告详情卡片。

详情卡片包含：

- 公告标题；
- 管控类型；
- 来源名称和来源等级；
- 发布时间；
- 生效时间与结束时间；
- 当前时间轴下的状态：生效中 / 未开始 / 已过期 / 时间未知；
- 管控区域描述；
- 航空器类型；
- AI 抽取置信度和地理解析置信度；
- 原文证据片段；
- 公告原文链接；
- 官方核验提示。

标准提示口径：

> 本系统基于公开公告展示低空管控风险，不构成飞行许可、审批结论或法律意见。实际飞行前仍需通过 UOM、空管、公安或公告发布单位进一步核验。

---

### 3.3 场景三：数据源与入库管理

运营人员或面试演示者进入后台，查看系统管理了哪些数据源，以及每个数据源最近一次采集结果。

系统支持：

- 查看国家部委 / 民航与空管公开信息、省市政府官网、公安官网、区县政府网站、景区公告、赛事活动官网、官方媒体等数据源；
- 查看来源等级、可信度评分、最近采集状态、有效公告数和待审核公告数；
- 手动触发一次采集；
- 新增或暂停数据源；
- 查看自动采集任务和手动提交任务；
- 点击“手动提交公告”补充系统暂未发现的公告链接或正文；
- 提交后自动生成入库任务，并进入 AI 解析和地图预览流程；
- 在同一页面查看质量概览、解析成功率、待核验任务数、证据绑定状态和安全文案指标。

这个场景用于解决两个问题：

1. 自动采集在 PoC 现场可能不稳定，需要一个可控的演示入口。
2. 产品正式化后，低空管控信息不能只依赖自动发现，还需要运营人员和企业客户补充线索。

## 4. PoC 范围

### 4.1 保留功能

| 模块 | PoC 做什么 | 目的 |
|---|---|---|
| 数据源管理 | 维护全国范围公开信息源，展示来源等级、覆盖区域、采集状态和有效公告数 | 体现数据产品后台能力 |
| 初始公告采集 | AI 自动搜索和抓取全国范围低空管控相关公开公告，一次性执行或手动触发 | 展示 AI 信息发现能力，并扩大样本发现空间 |
| 手动公告提交 | 在数据源管理页中提交公告链接或正文 | 补充自动发现遗漏，并支撑现场演示 |
| 入库任务管理 | 把自动采集和手动提交统一为 Ingestion Task | 让数据进入同一条可追踪管线 |
| AI 分类 | 判断公告是否与无人机 / 低慢小 / 临时禁飞相关 | 验证相关性识别 |
| AI 抽取 | 抽取标题、来源、时间、地点、管控类型和原文证据 | 验证结构化能力 |
| 地理解析 | 支持 POI + 半径、行政区、多点列表 | 验证地图化最小能力 |
| 时间状态判断 | 根据公告起止时间判断生效中、未开始、已过期、长期有效和未知 | 支撑地图时间轴 |
| 地图时间轴 | 在地图上拖动时间轴，切换不同时间点的管控图层状态 | 验证空间 + 时间可视化价值 |
| 图层详情 | 点击图层查看公告字段、证据、来源和核验提示 | 增强可信度和可解释性 |
| 质量概览与任务级评估 | 在数据源与入库管理页内展示解析成功率、低置信度任务、证据绑定、待核验原因、无证据图层和越权许可文案次数 | 保留 Evaluate 意识，但不单独增加页面复杂度 |

---

### 4.2 暂不做功能

| 暂不做 | 原因 |
|---|---|
| 用户侧 Agent 自然语言问答 | 当前场景核心是地图时空浏览，不是聊天；问答会增加幻觉和越权表达风险 |
| 飞行计划检查面板 | PoC 阶段不要求用户输入计划地点、高度、机型，先通过地图时间轴表达核心价值 |
| 地点 + 时间风险查询接口 | 不作为用户侧主链路，后续可作为地图点击或企业 API 能力扩展 |
| 长期定时监控全量数据源 | PoC 重点验证数据源管理和一次性采集能力，不验证长期运营稳定性 |
| 复杂多 Agent 自主调度 | 展示复杂度高，容易偏技术实现 |
| 普通用户公开提交并直接发布 | UGC 可信度风险高，PoC 阶段只作为运营 / 演示入口 |
| 完整人工审核后台 | PoC 可用入库任务表 + 简单人工确认替代 |
| 独立评估看板页面 | PoC 阶段评估能力融合进数据源与入库管理页，完整评测机制保留在方案文档中 |
| 生产级全国全量实时监控 | PoC 做全国开放搜索和样本沉淀，不承诺全量、实时、无遗漏 |
| 复杂道路合围自动落图 | 误画风险高，PoC 中标记为需人工核验 |
| 自动飞行申请 | 涉及官方审批，不适合 PoC |
| 判断“是否准飞” | 合规风险高，产品边界不清 |

## 5. PoC 核心链路

本版 PoC 将公告来源分为两类：**自动发现** 和 **手动提交**。两类入口最终进入同一条入库管线。

```text
公开数据源管理
   ↓
自动采集 / 手动提交
   ↓
生成入库任务 Ingestion Task
   ↓
正文获取与清洗
   ↓
AI 判断是否相关
   ↓
AI 抽取结构化字段和原文证据
   ↓
地理解析生成 geo_json
   ↓
时间状态归一化
   ↓
置信度评估与审核状态判断
   ↓
人工确认或自动通过
   ↓
发布地图图层
   ↓
用户在地图上拖动时间轴
   ↓
系统展示当前时间点生效 / 未开始 / 已过期 / 未知的图层
   ↓
用户点击图层查看公告详情、原文证据和官方核验提示
```

## 6. 数据结构设计

PoC 不追求完整生产级数据模型，但为了支撑数据源管理、手动入库、地图时间轴和证据回溯，本版建议保留三类核心对象：

1. `DataSource`：数据源
2. `IngestionTask`：入库任务
3. `Announcement`：结构化公告

`IngestionTask` 用于统一管理自动采集和手动提交。

```json
{
  "id": "task_001",
  "submit_channel": "manual",
  "submission_type": "text",
  "source_id": "src_001",
  "source_name": "杭州市某区政府网站",
  "source_url": "https://example.gov.cn/notice",
  "raw_text": "关于对无人机等低慢小航空器实施临时禁飞的通告……",
  "task_status": "parsed",
  "classification_result": "TEMP_NO_FLY",
  "is_relevant": true,
  "parse_confidence": 0.91,
  "geo_confidence": 0.88,
  "time_parse_status": "success",
  "review_status": "pending_confirm",
  "review_reason": null,
  "map_preview_status": "generated",
  "created_at": "2026-06-08 15:30:00",
  "created_by": "demo_user"

```

任务状态建议：

| 状态 | 说明 |
|---|---|
| `submitted` | 已提交，等待处理 |
| `fetching` | 正在获取正文 |
| `classifying` | 正在判断相关性 |
| `extracting` | 正在抽取字段 |
| `geo_parsing` | 正在解析地理范围 |
| `time_normalizing` | 正在归一化时间和有效状态 |
| `parsed` | 已完成解析 |
| `needs_review` | 需要人工核验 |
| `approved` | 已确认 |
| `published` | 已发布到地图 |
| `rejected` | 无关或不可信 |

## 7. 关键 AI 能力设计

### 7.1 数据源发现与筛选

PoC 支持从关键词和候选网站中发现公告来源。

输入示例：

```text
全国 无人机 禁飞 通告
全国 低慢小 管控 公告
省名/城市名 + 无人机 + 禁飞/管控/低慢小
景区 无人机 禁止飞行 通告
公安 无人机 管控 通告
高考/中考 无人机 禁飞 通告
赛事/演唱会/大型活动 无人机 管控 通告
```

城市词库可以按优先级轮询，例如北京、上海、广州、深圳、杭州、成都、重庆、武汉、南京、西安、长沙、厦门、三亚、昆明等。

---

### 7.2 入库任务分类

无论公告来自自动采集还是手动提交，系统都先判断其是否相关。

分类标签：

| 标签 | 含义 |
|---|---|
| `TEMP_NO_FLY` | 临时禁飞 |
| `TEMP_CONTROL` | 临时管控 |
| `REGISTRATION_NOTICE` | 备案通知 |
| `SAFETY_REMINDER` | 安全提醒 |
| `NON_RELEVANT` | 无关内容 |

---

### 7.3 字段抽取

PoC 重点抽取 9 个字段：

| 字段 | 示例 |
|---|---|
| 标题 | 关于对无人机等低慢小航空器实施临时禁飞的通告 |
| 发布单位 | 杭州市某区公安分局 |
| 来源 | 杭州市某区政府网站 |
| 开始时间 | 2026-06-07 08:00 |
| 结束时间 | 2026-06-10 18:00 |
| 时间状态依据 | 公告原文明确写明起止时间 |
| 管控类型 | 临时禁飞 |
| 管控区域 | 杭州奥体中心周边 1000 米 |
| 原文证据 | 对应公告原句 |

抽取原则：

- 所有关键字段必须绑定证据；
- 不确定字段返回 `null`；
- 不凭空补全地点、时间和政策判断；
- 低置信度结果标记为“需人工核验”；
- 手动提交内容也必须经过同样的抽取和证据绑定流程。

---

### 7.4 地理解析

PoC 只支持三类地理表达：

| 类型 | 示例 | 处理方式 |
|---|---|---|
| POI + 半径 | 杭州奥体中心周边 1000 米 | 地理编码 + buffer |
| 行政区 | 西湖区行政区域内 | 使用行政区边界 |
| 多点列表 | 各考点周边 500 米 | 批量 POI 解析 + buffer |

不做复杂道路合围区域，例如“东至某路、西至某路、南至某街、北至某街”。这类情况在 PoC 中标记为“区域模糊，需人工核验”，不自动发布为精确图层。

---

### 7.5 时间归一化与状态判断

时间轴依赖稳定的时间归一化能力。

时间状态枚举：

| 状态 | 判断逻辑 | 地图表现 |
|---|---|---|
| `active` | 时间轴当前时间处于公告开始和结束时间之间 | 高亮展示 |
| `not_started` | 时间轴当前时间早于开始时间 | 半透明或未来图层样式 |
| `expired` | 时间轴当前时间晚于结束时间 | 默认隐藏，可打开“历史公告”查看 |
| `long_term` | 无明确结束时间，且公告属于长期规则或长期管控 | 长期图层样式 |
| `unknown` | 时间缺失、冲突或语义模糊 | 灰色 / 待核验样式 |

特殊处理：

- “即日起”结合发布时间判断开始时间；
- “活动期间”“考试期间”如果无法解析具体日期，则标记为 `unknown`；
- “另行通知”不自动过期；
- 所有时间统一使用 Asia/Shanghai；
- 时间判断只影响地图展示状态，不等同于飞行许可。

---

### 7.6 PoC 中的 Agent 化设计

PoC 不实现复杂多 Agent 自主调度，但将 AI 能力拆分为 6 个可解释的任务 Agent。

| Agent | 输入 | 输出 | 价值 |
|---|---|---|---|
| Source Discovery Agent | 城市 + 关键词 | 候选数据源 / 候选公告链接 | 自动发现公开信息 |
| Ingestion Agent | URL / 正文 / 数据源采集结果 | 标准化入库任务 | 统一自动采集和手动提交 |
| Classification Agent | 公告正文 | 是否相关 + 公告类型 | 过滤无关内容 |
| Extraction Agent | 相关公告正文 | 时间、地点、管控类型、证据 | 把非结构化文本转成结构化数据 |
| Geo Parsing Agent | 区域文本 | `geo_type`、`center_poi`、`radius_meters`、`geo_json` | 生成地图图层 |
| Temporal Agent | 开始时间、结束时间、发布时间、语义表达 | `time_status`、`validity_basis` | 支撑地图时间轴 |

PoC 阶段采用顺序执行链路：

```text
Source Discovery / Manual Submit
   ↓
Ingestion Agent
   ↓
Classification Agent
   ↓
Extraction Agent
   ↓
Geo Parsing Agent
   ↓
Temporal Agent
   ↓
人工确认 / 发布地图
   ↓
地图时间轴展示
```

## 8. 数据源可信度与入库策略

### 8.1 来源等级

| 等级 | 来源类型 | PoC 处理策略 |
|---|---|---|
| P0 | 政府官网、公安官网、民航 / 空管官方页面 | 可进入自动通过或待确认流程 |
| P1 | 官方公众号、地方融媒体、政府新闻客户端 | 可入库和展示，但标记来源类型 |
| P2 | 主流媒体转载 | 可入库，但标记为转载来源，默认待人工确认 |
| P3 | 自媒体、聚合平台、论坛、社群截图 | 仅作为线索，不直接展示为正式公告 |

来源可信度评分可以由以下因素组成：

```text
Source Trust Score = 来源权威性 + 原文可追溯性 + 发布时间完整性 + 发布主体明确性 + 多来源一致性
```

### 8.2 全国数据源覆盖策略

全国范围不等于一开始做全量实时监控。PoC 采用“分层搜索 + 自然沉淀样本”的策略：

| 层级 | 来源示例 | PoC 处理方式 |
|---|---|---|
| 国家级 | 民航、空管、公安、文旅、体育赛事等公开通知 | 作为规则和权威来源基准 |
| 省级 | 省政府、公安厅、文旅厅、体育局、应急管理等官网 | 覆盖省级政策、重大活动和跨市管控 |
| 城市级 | 市政府、市公安局、市文旅局、市体育局、低空经济相关平台 | 作为主要公告发现来源 |
| 区县级 | 区县政府、公安分局、景区、学校、活动主办方 | 补充高频临时管控和具体区域信息 |
| 媒体转载 | 官方媒体、主流媒体、地方融媒体 | 辅助发现线索，默认保留来源等级和转载标识 |

搜索优先级规则：

1. 优先搜索政府、公安、民航 / 空管、景区、赛事、考试等公开来源；
2. 优先保留标题、发布时间、发布单位、管控时间和区域描述完整的公告；
3. 优先保留可被地理解析的样本，例如 POI + 半径、行政区、多点列表；
4. 不对省份、城市、数据源或公告数量设置硬性目标，搜索到多少有效样本就沉淀多少。

---

### 8.3 自动采集与手动提交的关系

| 入库方式 | 定位 | 发布规则 |
|---|---|---|
| 自动采集 | 系统从已登记数据源中发现候选公告 | 高置信度可进入待确认，低置信度需审核 |
| 手动提交 URL | 运营人员补充系统漏掉的公开链接 | 必须经过正文提取、分类、抽取、地理解析和确认 |
| 手动提交正文 | 适合公众号、截图 OCR 后文本、面试现场演示 | 必须保留提交内容和来源说明，不直接视为官方原文 |

手动提交不是绕过审核，而是创建一条新的入库任务。它的意义是提升覆盖率、降低现场演示不确定性，并给后续真实运营留下补充入口。

---

### 8.4 去重与冲突处理

同一公告可能被多个渠道转载。PoC 需要做轻量去重，避免地图上出现重复图层。

去重依据：

1. 标题相似度；
2. 发布时间接近度；
3. 发布单位一致性；
4. 管控时间一致性；
5. 管控区域一致性；
6. 正文语义相似度。

冲突处理规则：

| 冲突类型 | 处理方式 |
|---|---|
| 来源冲突 | 按 P0 > P1 > P2 > P3 排序，优先采用更权威来源 |
| 时间冲突 | 标记为“需人工核验”，不自动发布为确定图层 |
| 区域冲突 | 保留更权威来源，低权威来源作为补充证据 |
| 同一事件多版本 | 建立 `duplicate_group_id` 和 `version_id`，默认展示最新可信版本 |
| 原文缺失 | 仅作为线索，不进入地图正式图层 |

## 9.1 页面 1：地图浏览与时间轴页

### 页面目标

面向无人机飞行用户、航拍团队和面试演示对象，展示已解析的低空管控图层，并通过时间轴呈现公告在不同时间点的有效状态。

### 页面主结构

建议采用：

```text
顶部：地区选择 + 地点搜索 + 图层筛选
中部：全国 / 城市地图图层
底部：时间轴
左侧 / 右侧：图层详情卡片
右上角：图例与状态筛选
```

### 核心功能

- 默认展示已发布的公开低空管控图层；
- 支持按全国、省、市、区县筛选；
- 支持地点搜索，用于快速定位地图视野，但不触发 Agent 问答；
- 支持图层开关：临时禁飞、临时管控、备案提醒、待核验、历史公告；
- 支持时间轴拖动，查看不同时间点的图层状态；
- 支持快捷时间：现在、未来 24 小时、未来 7 天、历史公告；
- 点击图层查看公告详情、原文证据和来源链接；
- 对待核验图层使用灰色或虚线样式，避免模糊边界被误认为精确区域；
- 对已过期公告默认隐藏，用户打开“历史公告”后才展示。

### 时间轴设计

时间轴不承担“飞行计划检查”功能，而是承担地图状态切换功能。

建议交互：

| 组件 | 说明 |
|---|---|
| 当前时间指示线 | 默认显示系统当前时间 |
| 时间滑块 | 拖动后地图按该时间点刷新图层状态 |
| 时间范围选择 | 可切换“当前 / 未来 24 小时 / 未来 7 天 / 历史” |
| 状态统计 | 展示当前时间点生效中、未开始、已过期、未知的图层数量 |
| 播放按钮 | 可选，自动播放未来 7 天图层变化，增强演示效果 |

示例状态：

```text
时间轴：2026-06-08 15:00
生效中：8
即将生效：3
已过期：12（默认隐藏）
待核验：5
```

### 地图图层样式建议

| 图层类型 | 样式建议 | 含义 |
|---|---|---|
| 临时禁飞 | 红色实线 / 半透明填充 | 当前时间点存在公开禁飞公告 |
| 临时管控 | 橙色实线 / 半透明填充 | 当前时间点存在公开管控公告 |

## 10. 地图图层与时间轴规则

### 10.1 图层风险类型

| 类型 | 判断条件 | 用户文案 |
|---|---|---|
| 临时禁飞 | 公告明确包含临时禁飞、禁止飞行等表达 | 该区域存在公开临时禁飞公告风险 |
| 临时管控 | 公告包含管控、限制、审批、报备等表达 | 该区域可能需要审批、备案或进一步核验 |
| 备案 / 安全提醒 | 公告不构成禁飞，但提醒登记、备案或安全要求 | 请按官方要求完成核验和备案 |
| 待核验 | 时间、来源、边界或证据不完整 | 暂无法可靠展示为确定图层，请以官方信息为准 |
| 历史公告 | 当前时间轴晚于公告结束时间 | 仅作历史参考，不代表当前状态 |

### 10.2 时间轴展示规则

| 场景 | 判断 | 地图处理 |
|---|---|---|
| 时间轴时间在公告有效期内 | `start_time <= selected_time <= end_time` | 展示为生效中 |
| 时间轴时间早于公告开始时间 | `selected_time < start_time` | 展示为未开始 / 未来生效 |
| 时间轴时间晚于公告结束时间 | `selected_time > end_time` | 默认隐藏，开启历史公告后展示 |
| 公告无明确结束时间但属于长期规则 | `time_status = long_term` | 持续展示为长期有效 |
| 公告时间字段缺失或冲突 | `time_status = unknown` | 展示为待核验或不落图 |
| 地理边界无法可靠解析 | `geo_confidence` 低或复杂合围 | 不精确落图，仅显示待核验提示 |

### 10.3 不做点位命中判断

本版 PoC 不做“用户输入一个飞行计划后判断是否命中某区域”的交互，也不要求用户填写飞行高度和机型。

原因：

1. 地图图层 + 时间轴已经能表达当前核心价值；
2. 点位命中查询容易让用户误解为“系统给出飞行许可”；
3. 飞行高度、机型、实名登记、审批状态等因素涉及更多合规变量，不适合作为 PoC 主链路；
4. 后续如果要做企业 API 或任务规划，可以在地图图层能力稳定后再扩展点位查询。

## 12. Evaluate 分层设计

PoC 的 Evaluate 不再以独立页面呈现，而是分成两层：

1. **页面内质量监控**：融合在数据源与入库管理页中，展示与当前入库链路直接相关的质量状态。
2. **方案级评测机制**：保留 Golden Dataset、核心指标和红队测试，用于说明后续如何持续评估 AI 质量、安全边界和成本。

这样既能体现 Evaluate 意识，又不会让 PoC 页面过重。

---

### 12.1 页面内质量监控

页面内只展示过程型、可解释、和入库任务强相关的指标。

| 监控位置 | 展示内容 | 目的 |
|---|---|---|
| 顶部质量概览 | 候选公告数、有效公告数、待核验数、已落图数、解析成功率 | 说明本轮链路是否跑通 |
| 数据源列表 | 来源等级、最近采集状态、有效公告数、异常次数 | 评估数据源是否稳定和有效 |
| 入库任务表 | 解析状态、时间抽取、时间状态、地理解析、证据绑定、置信度、审核状态 | 评估每条公告是否可发布 |
| 解析详情 Drawer | 字段证据、置信度、时间轴预览、地图预览、审核原因 | 解释 AI 输出为什么可信或为什么需要人工确认 |
| 页面文案检查 | 无证据图层数、越权许可文案次数 | 守住安全和合规底线 |

页面内不展示复杂算法指标，例如 MRR@10、完整 Recall@5 曲线、模型灰度对比等。这些指标保留在方案级评测机制中。

---

### 12.2 方案级评估对象

| 评估层 | 评估内容 | 核心问题 |
|---|---|---|
| 数据源评估 | 来源是否权威、是否稳定、是否贡献有效公告 | 系统是不是接入了正确来源 |
| 入库任务评估 | 自动采集和手动提交是否能完成解析 | 公告能不能顺利进入管线 |
| 公告识别评估 | 是否识别出真正相关公告 | 有没有漏掉重要公告 |
| 字段抽取评估 | 时间、地点、区域、类型是否正确 | 结构化结果是否可信 |
| 时间归一化评估 | 起止时间、长期有效、未知状态是否判断正确 | 时间轴展示是否可靠 |
| 地理解析评估 | POI、半径、行政区、多点列表是否解析正确 | 地图图层是否可靠 |
| 证据回溯评估 | 图层字段是否绑定正确原文证据 | 用户点击图层后是否可追溯 |
| 安全文案评估 | 是否越权承诺、是否提供规避建议 | 是否守住产品边界 |
| 人工审核评估 | 低置信度是否被拦截 | 是否把不确定问题交给人 |

---

### 12.3 Golden Dataset

PoC 阶段不强制规定 Golden Dataset 的固定规模，而是将搜索到的有效公告、无关公告、复杂边界样本和手动提交样例持续沉淀为评测集。

建议样本类型：

| 样本类型 | 作用 |
|---|---|
| 全国无人机 / 低慢小相关公告 | 评估相关公告识别、字段抽取和地图化能力 |
| 相似但无关公告 | 评估误召回和分类边界 |
| 图片或 PDF 公告 | 评估正文提取、OCR 和版面解析能力 |
| POI + 半径类区域 | 评估最小可落图能力 |
| 行政区类区域 | 评估行政边界匹配能力 |
| 多点列表类区域 | 评估批量 POI 解析能力 |
| 复杂道路合围类区域 | 评估是否能正确拦截复杂边界，避免误画 |
| 时间表达复杂样本 | 评估“即日起”“活动期间”“另行通知”等时间归一化 |
| 安全文案样本 | 评估是否出现越权许可或规避建议 |
| 手动提交样例 | 评估人工补充入口是否能进入统一入库流程 |

---

### 12.4 核心评估指标

这些指标不需要全部做成 PoC 页面，但需要在方案中说明后续如何评估。

| 模块 | 指标 | 目标 |
|---|---|---:|
| 数据源管理 | 有效来源识别率 | 可从搜索结果中识别并保留权威来源 |
| 入库任务 | 任务解析成功率 | ≥ 90% |
| 公告分类 | 相关公告召回率 | ≥ 95% |
| 公告分类 | 相关公告准确率 | ≥ 90% |
| 字段抽取 | 时间字段抽取准确率 | ≥ 90% |
| 字段抽取 | 区域字段抽取准确率 | ≥ 85% |
| 字段抽取 | 管控类型准确率 | ≥ 90% |
| 时间归一化 | 时间状态判断准确率 | ≥ 90% |
| 证据绑定 | 原文证据覆盖率 | 100% |
| 地理解析 | POI 解析准确率 | ≥ 90% |
| 地理解析 | 半径抽取准确率 | ≥ 95% |
| 地理解析 | 复杂边界误画率 | 0% |
| 图层展示 | 图层信息展示覆盖率 | 100% |
| 安全文案 | 越权许可文案次数 | 0 次 |
| 安全文案 | 规避监管建议次数 | 0 次 |
| 成本 | 单条有效公告处理成本 | 可量化并持续下降 |
| 成本 | 单次地图图层加载成本 | 可量化并可缓存优化 |

---

### 12.5 红队测试问题与文案检查

本版不做 Agent 问答，但仍要检查页面文案是否越界。

需要拦截的文案类型：

1. “该区域可以飞”；
2. “没有公告，所以可以飞”；
3. “低风险等于无需报备”；
4. “249g 无人机不受限制”；
5. “绕开红色区域即可飞行”。

期望页面表达：

- 不承诺“可以飞”；
- 不提供规避监管建议；
- 命中公告时展示原文证据；
- 未命中或未展示公告时，也不等同于许可；
- 所有图层详情必须包含官方核验提示。

## 14. 面试讲述重点

### 14.1 用户痛点

无人机用户在飞行前很难快速了解某个城市或区域是否存在临时禁飞或管控公告，因为公告可能分散在政府网站、公安通告、景区通知、赛事公告和媒体转载中。

用户并不一定需要和 Agent 对话。很多时候，他们更需要在地图上看到：

- 当前有哪些公开管控区域；
- 哪些区域现在生效；
- 哪些区域未来会生效；
- 哪些公告已经过期；
- 每个图层来自哪条公告和哪句证据。

---

### 14.2 产品价值

本产品不是审批工具，而是一个“公告情报地图”。

它帮助用户：

- 自动发现分散在各处的公开公告；
- 管理低空管控数据源；
- 通过手动补充入口弥补自动发现遗漏；
- 浏览全国范围内公开空域管控信息，并支持按省、市、区县筛选；
- 通过时间轴查看图层的生效、未开始、已过期和未知状态；
- 查看原文证据和官方核验提醒。

---

### 14.3 AI 价值

AI 的作用不是直接回答“能不能飞”，而是完成五件事：

1. 自动发现和筛选公开公告来源；
2. 将自动采集和手动提交统一转成可处理的入库任务；
3. 从非结构化公告中提取时间、地点、管控类型等结构化字段；
4. 将自然语言区域转成可用于地图展示的空间信息；
5. 将时间表达转成可用于时间轴展示的标准状态，并绑定原文证据。

---

### 14.4 产品边界

系统不会回答“你一定可以飞”，也不会提供规避监管建议。所有低置信度、来源不可靠、边界模糊或时间不明确的情况，都提示用户进行官方核验。

手动提交内容不会绕过审核直接发布。它只是补充入库入口，仍然必须经过 AI 解析、证据绑定、地理解析、时间归一化、置信度评估和人工确认。

PoC 阶段验证全国开放搜索下的数据源管理、一次性采集、手动补充、地图化展示和时间轴状态切换，不验证生产级全国全量实时监控，也不承诺覆盖固定数量的城市、数据源或公告。

## 16. ROI 与成本模型

### 16.1 为什么 PoC 阶段也要考虑 ROI

本 PoC 虽然主要用于验证 AI 是否能完成公告发现、结构化抽取、地图化展示和时间轴状态切换，但如果后续作为正式产品，需要提前评估单位经济模型。

本产品的核心成本不只是大模型调用费，还包括数据源维护、搜索抓取、OCR、地理编码、地图服务、人工审核和系统运维。因此，PoC 阶段需要验证三个关键成本指标：

1. 单条公告从发现到地图化的处理成本；
2. 单次地图图层加载和时间轴切换成本；
3. 单个企业客户的月度服务成本。

### 16.3 单条公告处理成本

```text
C_announcement =
C_ingestion
+ C_fetch_or_clean
+ C_ocr
+ C_classification
+ C_extraction
+ C_temporal_normalization
+ C_geocoding
+ C_storage
+ P_review × C_human_review
```

其中：

- `C_ingestion`：自动采集或手动提交产生的入库成本；
- `C_fetch_or_clean`：网页抓取或手动文本清洗成本；
- `C_ocr`：OCR 成本，纯网页文本可接近为 0；
- `C_classification`：公告相关性判断成本；
- `C_extraction`：字段抽取成本；
- `C_temporal_normalization`：时间归一化和状态判断成本；
- `C_geocoding`：地图地理编码成本；
- `C_storage`：原文、结构化字段和图层存储成本；
- `P_review`：进入人工审核的比例；
- `C_human_review`：单条人工审核成本。

PoC 阶段重点观察：

```text
单条有效公告成本 = 全部候选公告处理成本 / 最终有效公告数量
```

### 16.4 单次地图图层加载成本

```text
C_map_view =
C_map_tiles
+ C_layer_query
+ C_time_filter
+ C_spatial_render
+ C_log
```

优化方向：

1. 按城市或视野范围加载图层，避免一次性加载全国全量；
2. 对时间轴常用时间点进行缓存，例如当前、未来 24 小时、未来 7 天；
3. 历史公告默认隐藏，降低图层渲染压力；
4. 图层详情按需加载，点击后再读取证据和原文链接；
5. 已发布公告的时间状态可预计算，减少前端实时计算压力。

## 17. 模型选型与评测机制

### 17.1 模型选型原则

本产品不采用单一大模型完成所有任务，而是按照任务复杂度进行模型分层。

模型选型主要考虑 8 个维度：

| 维度 | 说明 |
|---|---|
| 准确率 | 是否能稳定识别公告类型、时间、地点、管控区域 |
| 成本 | 单条公告处理和地图图层加载成本是否可控 |
| 延迟 | 数据入库和地图展示是否在可接受时间内完成 |
| 中文能力 | 是否能理解政府公告、公安通告、政策表述 |
| 结构化输出能力 | 是否能稳定输出 JSON，并遵循字段约束 |
| 长文本能力 | 是否能处理长公告、附件、表格和多段政策文本 |
| 工具调用能力 | 是否能配合搜索、地理编码、数据库查询等工具 |
| 安全与可控性 | 是否能避免越权判断、幻觉和规避监管建议 |

---

### 17.2 模型分层策略

| 任务 | 推荐模型策略 | 原因 |
|---|---|---|
| 关键词初筛 | 规则 + 轻量模型 | 成本低，处理大量候选页面 |
| 数据源评级 | 规则 + 轻量模型 | 任务较稳定，可解释性要求高 |
| 公告相关性分类 | 小模型或中等模型 | 任务明确，不需要最强模型 |
| 字段抽取 | 中高能力模型 | 需要稳定结构化输出和证据绑定 |
| 时间归一化 | 规则 + 中等模型 | 大多数时间表达可规则处理，模糊表达交给模型 |
| 地理表达解析 | 中高能力模型 + 地图工具 | 需要理解自然语言区域并调用地理编码 |
| 图层摘要生成 | 中等模型 + 模板 | 只用于详情卡片解释，不做飞行许可判断 |
| 安全文案检查 | 规则 / 评估模型 | 检查页面文案是否越权、是否缺少官方核验提示 |
| 批量离线处理 | 成本优先模型 | 可牺牲部分实时性，控制成本 |
| 低置信度复核 | 高能力模型 + 人工审核 | 处理复杂、模糊、冲突场景 |

---

### 17.3 模型级联设计

```text
规则过滤
   ↓
小模型分类
   ↓
中模型抽取
   ↓
规则 + 模型进行时间归一化
   ↓
高能力模型处理复杂样本
   ↓
低置信度进入人工审核
```

手动提交内容也进入同一套级联策略，避免因为“人工提交”而降低质量门槛。

## 18. 面试中的一句话总结

这是一个面向低空飞行场景的 AI 公告情报地图 PoC。它通过数据源管理和入库任务机制，把自动采集和手动补充的公开低空管控信息统一纳入 AI 解析流程，利用 LLM 抽取时间、地点、管控类型和原文证据，将公告转化为空域图层，并通过地图时间轴展示不同时间点的生效、未开始、已过期和待核验状态。系统不做 Agent 问答，不要求用户填写飞行计划，不替代官方审批，也不直接判断“是否准飞”。
